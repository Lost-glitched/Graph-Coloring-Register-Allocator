# Graph-Coloring Register Allocator

## Overview

This register allocator accepts a small **Three-Address Code (3AC)** intermediate representation containing an arbitrary number of virtual registers and allocates them to exactly `K` available physical registers (`R0`, `R1`, ..., `R(K-1)`).

When register pressure exceeds `K`, the allocator spills variables to stack slots and rewrites the IR with explicit `LOAD`/`STORE` instructions, iterating until all variables are successfully allocated.

## Algorithm Design

The allocator implements the full Chaitin-Briggs pipeline:

```
3AC / IR Input
    ↓
Parsing (text → IR)
    ↓
Basic Block + CFG Construction
    ↓
Backward Data-Flow Liveness Analysis
    ↓
Interference Graph Construction (Chaitin's MOV rule)
    ↓
Move Detection + Conservative Coalescing (Briggs' criterion)
    ↓
Simplify (push degree < K nodes)
    ↓
Freeze move-related low-degree nodes when coalescing is blocked
    ↓
Optimistic Spill Selection (degree ≥ K, lowest cost)
    ↓
Select / Graph Coloring (pop stack, assign registers)
    ↓
If actual spills: IR rewriting with LOAD/STORE → rebuild CFG/liveness/interference and repeat
    ↓
Final Allocated IR
```

Key algorithmic features:

| Feature | Implementation |
|---------|---------------|
| **Liveness** | Iterative fixed-point, block-level then instruction-level |
| **Interference** | Chaitin's MOV exception (move src/dest don't interfere through the move) |
| **Coalescing** | Briggs' conservative criterion |
| **Simplify** | Deterministic (lexicographically smallest variable) |
| **Spill selection** | Optimistic — candidates are given a chance to color |
| **Spill rewriting** | Fresh temporaries per use/def, short live ranges |
| **Termination** | Max 50 rounds with progress detection |

## IR Syntax

The input language is a simple line-oriented 3AC:

```text
# Comments start with '#'

# Assignment (copy)
dest = src

# Arithmetic
dest = src1 + src2
dest = src1 - src2
dest = src1 * src2
dest = src1 / src2

# Memory (generated by spill rewriting)
LOAD dest, [slot]
STORE src, [slot]

# Control flow
GOTO label
IF condition GOTO label
LABEL label_name
```

Variable/label names are arbitrary alphanumeric identifiers. There is no limit on the number of virtual registers.

## Architecture

```
include/
├── Instruction.h          Opcode enum + instruction struct with def/use queries
├── IRProgram.h            Instruction container with rename/clone utilities
├── Parser.h               3AC text parser
├── BasicBlock.h           Basic block with predecessor/successor pointers
├── ControlFlowGraph.h     CFG construction (leaders, edges)
├── LivenessAnalyzer.h     Block-level and instruction-level liveness
├── InterferenceGraph.h    Undirected graph with remove/restore/merge
├── MoveGraph.h            Move-related pair tracking
├── Coalescer.h            Briggs' conservative coalescing
├── SpillCostAnalyzer.h    Spill cost heuristic computation
├── RegisterAllocator.h    Main Chaitin-Briggs driver
├── SpillRewriter.h        IR rewriting for spilled variables
└── AllocationResult.h     Final assignment map and output formatting

src/
├── *.cpp                  Implementations of all above
└── main.cpp               Demo driver

tests/
└── test_main.cpp          22 automated test cases
```

All modules are decoupled and testable independently.

## Coalescing Strategy

**Briggs' conservative coalescing criterion** is used:

> Two move-related nodes `a` and `b` can be safely coalesced if the merged node `(a,b)` would have fewer than `K` neighbors of **significant degree** (degree ≥ K in the merged graph).

This guarantee ensures that coalescing never makes an otherwise K-colorable graph uncolorable.

When computing the degree of neighbors in the merged graph:
- If neighbor `n` was adjacent to both `a` and `b`, its degree decreases by 1 (the duplicate edge collapses)
- If neighbor `n` was adjacent to only one, its degree remains unchanged

Coalescing iterates until no more safe merges are possible in the current round.

## Spill-Cost Heuristic

```
spill_cost(v) = Σ (10^loop_depth for each use/def of v) / max(degree(v), 1)
```

- **Loop depth** is estimated via back-edge detection in the CFG using DFS
- **Higher loop depth** → exponentially higher cost (variables inside loops are expensive to spill)
- **Division by degree** → prefers spilling high-degree nodes (removing more interference edges)
- **Lower cost = better spill candidate** (the cheapest variable to spill is selected first)
